# iOS 0.16.2 Build18 修复记录

## 循环播报（已定位）

Build17 的提交 `58b9e47` 在每次刷新时从近到远遍历播报档位，却仅保存上一次的 key。
距离小于 200 米后，转向事件会在 200/500 档位间切换；红绿灯小于 60 米后同样会在
60/300 档位间切换。不断加入系统语音队列后，听起来会一直重复首次指引。

现在按每个转向分段、每盏灯保存已到达的最近档位，状态只向更近的档位推进。
起步或定位跳变直接进入近档时跳过远档，停车和距离抖动不会重播。新导航及成功重算路线
会重置播报状态；转向 200 米内继续让位给转向播报，同一帧已有转向播报时延后灯位提示。
红绿灯远档文案使用实际距离，不再将 80 米说成 300 米。

## 初次规划提示未登录（部分修正，原始现场原因待确认）

Build16 基线已将摩托车接口的所有非成功响应及空路线统一描述为需要检查登录或验证。
红绿灯补丁未修改这部分。现有用户反馈不足以判断首次规划失败是否由网页会话、网络、
起终点或高德服务引起，不能把错误提示当成账号失效的证据。

- 无路线、格式异常、服务错误分别提示；仅明确的登录/验证返回提示处理账号。
- 验证页带入刚才规划的起终点及途经点，用户完成后可直接重试。
- 沿用本机持久 WK Cookie 和原有域名过滤，不导出、打印或扩大 Cookie 作用域。
- 自行车走高德 iOS 搜索接口，不使用网页登录；保留可见错误码，对常见 Key/权限错误给出针对提示。
  错误码参考：[高德官方文档](https://lbs.amap.com/api/ios-sdk/guide/map-tool/errorcode/)。

## 验证

CI 原有入口已包含新增回归：

```sh
python3 ios/tests/webmotor/check.py
python3 ios/tests/reroute-recovery/run.py
```

前者验证档位抖动、跳过远档、错误分类及不回显服务原文；后者运行生产导航会话和
render 方法，覆盖停车连续刷新、模拟导航、连续多个灯位、转向优先及重新开始。
构建结果以对应修复分支的 macOS CI 为准；真机登录、冷启动和道路导航仍需安装后确认。

真机复测建议：完全退出后分别直接规划摩托车/自行车；摩托车在距首个转向不足 200 米时
开始模拟导航并暂停，再恢复观察；如规划失败，记录完整提示及错误码、网络类型、是否刚启动。
无需提供账号 Cookie、Key 或个人路线数据。
