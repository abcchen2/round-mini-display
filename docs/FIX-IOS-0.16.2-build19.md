# iOS 0.16.2 Build19

在 Build18 的循环播报、规划错误提示修复之上，修复源码复查确认的四项问题。

## GPS 长时间中断后恢复

原跟踪器将可接受位移封顶在 2250 米左右；更远的新定位会被丢弃，却不更新物理位置基准，
可能导致隧道后持续无法恢复。现在正常连续定位仍使用原门限；长时间中断后，至少两笔精度合格、
时间递增且相互一致的定位确认恢复。仅在两笔定位均有唯一且一致的沿程投影时推进进度。
共享顶点属于同一路段，环线多次经过或偏离路线不能用单个最近点猜测进度。

投影多义时保持路线进度，用已确认的新位置重新规划；跨失败、冷却与重试期间持续抑制旧转向。
手机地图显示恢复的真实位置，方向和距离改为核对路线状态。恢复当帧不触发到达。

## 分享路线不再用路名猜转向

原分享路线将道路名称直接作为动作，导致“左家庄路”等名称被当成左转。
同时分段起点始终为 0，后面道路名覆盖前面路段。现在正确维护每段起点，保留原轨迹和文本，
缺少可信转向动作的分享路线明确标为仅路线跟随，不生成虚假的左转、右转或直行命令。
红绿灯事件仍可在几何匹配可靠时独立提醒。

**现有圆屏固件限制：** 无转向路线在手机上继续显示路线地图和位置；圆屏使用已有中性等待指引画面，
不会显示完整路线地图。App 预览已注明此行为。圆屏的独立“仅地图、无转向”模式需另行升级固件协议，
本次不要求刷固件。正常 App 内规划并有完整分段的路线保留原导航能力。

## 真实导航等待第一笔有效定位

真实导航开始时速度为 0，位置为空，手机和圆屏显示等待定位；不使用模拟速度、规划起点或正常定位标记。
首笔有效定位后才发送实际位置、测量车速与转向提示；模拟导航保留所选速度。

## 蓝牙重连设置

无逗号的 `#M0/#M1` 与 `#L…` 分别按指令名缓存，而非把每个值当成独立状态。
开关或数值往返修改后，离线队列、重连重放和设置同步都只保留当前值。
